# MCP-Hands — дизайн-док (черновик v0.1)

Дата: 17.10.2026. Статус: черновик для ревью. Владелец: Bileneret.

---

## 1. Суть проекта

Локальный «исполнительный слой» (глаза + руки) для computer-use на Windows.
Старшая LLM («мозг») думает редко и дорого; локальные рефлексы делают рутину
быстро и дёшево. Главная цель — ускорение и удешевление computer-use по сравнению
с классической схемой «скриншот → облако → клик» (решение Q50).

## 2. Цели и не-цели v1

**Цели:**
- автономное выполнение 10 задач бенчмарка (раздел 7) на Windows 11;
- восприятие UIA-first; действия API-first; локальная VLM как пиксельный фоллбэк;
- стоп-листы и «человек в цикле» (пауза + уведомление с кнопками);
- публикуемые метрики: время, токены, процент успеха, число вмешательств;
- приватность: локальная обработка по умолчанию; в облако уходит минимум
  (структурированные текстовые описания, пиксели — только по необходимости).

**Не-цели v1 (сознательно отложено):**
- кроссплатформенность (только Windows);
- MCP-мост (второй режим интеграции — отдельный этап после v1);
- полный undo действий (нереализуем в общем случае; компенсируют чекпойнты);
- игры и всё, что связано с античитами;
- сценарии с оплатой/отправкой/публикацией (запрещены политикой, см. 5).

## 3. Роли и пользователи

- **Владелец (Bileneret)** — главный пользователь, арбитр, приёмка.
- **Тест-пользователи** — 1–2 знакомых, после внутренней стабилизации (этап 4).
- **Публичный релиз** — BYOK (пользователь вставляет свой ключ LLM) как основной путь;
  бесплатные модели — «демо-режим»; добровольная монетизация (donate).

## 4. Архитектура: мозг / глаза / руки

### 4.1 Мозг (планировщик)
- Единый интерфейс: OpenAI-совместимый (`base_url + api_key + model`).
  Провайдеры: River (dev: DeepSeek-V4.1-Flash, приём изображений подтверждён),
  Google AI Studio, OpenRouter, локальные — переключаются конфигом.
- Режимы ответа: (а) tool-calling — если модель поддерживает (проверяется тестом
  при подключении); (б) JSON-план по промпту — работает всегда и остаётся
  запасным каналом даже при наличии (а).
- **План реактивный (closed-loop), а не линейный**: каждый шаг содержит действие
  И ожидаемое постусловие, например
  `{"action": "click", "target": {...}, "expect": {"event": "WINDOW_OPEN", "title_regex": "Сохранение", "timeout_ms": 1500}}`.
  Постусловие не наступило — локальный рефлекс (повтор/перепланирование),
  а не слепое продолжение цепочки (класс ошибок «кликнули в пустоту»).
- В контекст передаётся структурированное текстовое описание UI; скриншоты —
  только по явному требованию планировщика (экономия токенов).
- Параметры (reasoning: disabled/low/high/max, max_tokens, temperature) — конфигом.

### 4.2 Глаза (восприятие)
- **Уровень 1 — UI Automation** (основной): дерево элементов, событийные подписки.
  Обязательные правила (иначе COM-поток виснет на 5–15 с на Electron/Chromium):
  `IUIAutomationCacheRequest` — все нужные свойства за один межпроцессный переход;
  ограничение области — `TreeScope_Children`, глубина ≤ 3; работа только через
  процесс-зонд с IPC-таймаутом 500 мс; нет ответа — зонд снимается (`kill`),
  включается пиксельный фоллбэк.
- **Уровень 2 — локальная VLM**: Qwen3-VL-2B-Instruct (INT4, ~2 ГБ VRAM),
  ленивая загрузка (поднять → поработать → выгрузить). Для «неизведанных»
  приложений, canvas, картинок: выдаёт структурированное описание + координаты.
  На вход — **кроп активного окна** (`GetForegroundWindow` + его прямоугольник),
  а не весь рабочий стол: мелкие иконки на полном кадре сжимаются в 1–2
  токена-патча и grounding промахивается; кроп поднимает точность в разы
  и ускоряет инференс.
- **Уровень 3 — облачные зрение** (опция, по требованию): Gemini 3.8 Flash,
  Computer Use Preview, бесплатные vision-модели.
- Захват экрана для пиксельного пути: DXGI Desktop Duplication (готовые
  Python-обвязки); мультимонитор с учётом per-monitor DPI.

### 4.3 Руки (действия)
- **API-first**: сначала программный интерфейс — UIA-паттерны; Office — COM;
  браузер — CDP/DOM (опыт connect4 переносится). Физический ввод — только если
  программный путь невозможен.
- Физический ввод: SendInput (абсолютные координаты, DPI-aware); человекоподобные
  траектории (разброс, паузы, шум) — опциональный режим.
- Драйверный ввод — не в v1 (резерв).
- **CoordinateSpace — обязательный класс-транслятор**: UIA отдаёт логические
  DIP-координаты, DXGI/VLM — физические пиксели, `SendInput` требует нормализованные
  0..65535 относительно виртуального экрана. Все переходы — через один модуль,
  с привязкой окна к монитору (`MonitorFromPoint`); иначе систематические промахи
  кликов на 5–50 px при масштабе ≠ 100%.

### 4.4 События и тайминги
- `SetWinEventHook` (появление/активация окон, изменения), `ReadDirectoryChangesW`
  (файлы), монотонные таймеры QPC вместо пауз «на глазок».

### 4.5 Память
- SQLite: сценарии, история запусков, карты элементов, версии приложений.
- Позже: embeddings (Gemini Embedding или локальные) для поиска похожих ситуаций.

## 5. Безопасность и политика

Четыре уровня, все проверяются **в коде исполнителя** (LLM не может ни отменить,
ни «переубедить» их):
0. Неизменяемое ядро: системный диск и системные каталоги — только чтение;
   любые удаления — только в корзину; изменение системных файлов/драйверов запрещено.
1. Стоп-лист пользователя (конфиг): приложения, папки, эвристики по локализованным
   именам кнопок («Отправить/Send», «Оплатить/Pay», «Опубликовать/Publish», «Удалить/Delete»).
2. Серая зона → пауза и запрос человеку (уведомление с кнопками
   «Продолжить / Помочь / Стоп»).
3. Разрешено.

Жёсткие правила:
- кнопки «Отправить/Оплата/Опубликовать» — запрещены даже в полном доступе
  (заполнить форму, приложить файлы — можно; нажать отправку — нет);
- никогда не нажимать «Да/OK» в незнакомых диалогах подтверждения вслепую;
- prompt-injection: инструкции — только от пользователя; содержимое экрана — данные;
- детект вмешательства пользователя (мышь/клавиатура) → пауза, не борьба за ввод;
- журнал: этап разработки — полный (лог + видеозапись сессии), релиз — текстовый лог;
- быстрый стоп: глобальная горячая клавиша; dry-run-режим («показать план, не исполнять»);
- визуализация dry-run и «серой зоны»: полупрозрачная подсветка целевого элемента
  поверх экрана (click-through окно `WS_EX_TRANSPARENT | WS_EX_LAYERED`) — человек
  видит, куда агент собирается нажать, до подтверждения (перенос оверлея connect4);
- опасные приёмочные тесты — только в Windows-VM (VirtualBox/VMware + снапшоты).

## 7. Бенчмарк (10 задач, из реальной рутины)

1. Word: титульный лист + структура отчёта по шаблону.
2. Word: форматирование документа (стили, шрифты, интервалы, оглавление).
3. Word → PDF: сохранение по шаблону имени.
4. Браузер: собрать источники по теме в таблицу (автор, год, ссылка).
5. Браузер: текст статьи → в Word с оформлением цитаты.
6. Браузер: разобрать сессию вкладок (сгруппировать, сохранить, закрыть лишнее).
7. YouTube: найти видео, субтитры/скорость, выписать таймкоды в заметки.
8. Файлы: разобрать папку загрузок по типам (удаление — только в корзину).
9. Excel/CSV: свести данные из файлов + построить график.
10. Комбо-витрина: «отчёт по лабе» — поиск → таблица → оформление → PDF.

Метрики каждой задачи: время агента vs время человека, токены, % успеха,
число вмешательств пользователя.

## 8. Этапы и критерии «готово»

**Этап 0. Спайк (2–3 дня).** Замеры: UIA (включая таймаут зонда 500 мс и лимит
глубины ≤ 3), DXGI-захват, SendInput, событийные хуки; транслятор координат при
масштабах 100/125/150%; кроп активного окна для VLM; установка и один прогон
Qwen3-VL-2B. Критерий: цифры замеров + прототип «увидел экран → нашёл элемент → кликнул».

**Этап 1. Ядро без LLM.** Сенсоры, актуаторы, событийный слой; 3 сценария
на чистом Python. Критерий: сценарии проходят детерминированно, повторяемо.

**Этап 2. Мозг, память, политики.** Планировщик (JSON-план), стоп-листы,
SQLite-память, режимы ответа. Критерий: 10 задач бенчмарка запускаются end-to-end.

**Этап 3. Надёжность.** Пост-верификация шагов, чекпойнты, восстановление после
сбоев и закрытия окон, обработка незнакомых диалогов. Критерий: ≥70% задач
без вмешательства (порог уточняется после этапа 0).

**Этап 4. Бенчмарк и метрики.** Прогон 10 задач, сводные цифры, опционально —
сравнение с Computer Use Preview. Критерий: публикуемые воспроизводимые метрики.

**Этап 5. Релиз.** README (RU/EN), демо-видео, лицензия, публикация, donate.
Критерий: репозиторий готов к публичному показу.

## 9. Риски и митигации

- **UIA-хрупкость** (Electron/веб): гибрид с VLM-фоллбэком; изоляция UIA
  в отдельном процессе-зонде, чтобы зависания не вешали агента.
- **Слабое планирование дешёвых моделей**: шаблоны сценариев + память +
  строгая JSON-валидация планов.
- **4 ГБ VRAM**: одна модель за раз, ленивая загрузка, INT4.
- **Этика/право**: управление чужими приложениями → стоп-листы, VM для тестов,
  прозрачный журнал.
- **Локализация**: тесты на русской Windows (кириллица в OCR и эвристиках).
