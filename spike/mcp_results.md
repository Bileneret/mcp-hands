# Спайк MCP (этап 2, шаг 0) — результаты

Дата: 17.10.2026. Стенд: Windows 11 (26120), Python 3.12.0 в `.venv`,_transport stdio,
клиент и сервер в отдельных процессах. Артефакты: `mcp_hello_server.py`, `mcp_hello_client.py`,
замер попытки — `results_mcp.json`.

## Что проверено

1. **SDK установлен**: официальный `mcp` 2.3.0 (+ `mcp-types` 2.3.0). Зависимости лёгкие:
   pydantic 2.14, anyio, starlette/uvicorn, jsonschema, typer. **Карантинных гостей нет**
   (ни браузеров, ни torch — урок шага 8 с Playwright).
2. **API 2.x**: класс `FastMCP` переименован в `MCPServer` (`mcp.server.mcpserver`);
   декоратор `@server.tool()`; запуск — `anyio.run(server.run_stdio_async)`.
   Клиентский API остался классическим: `stdio_client(StdioServerParameters)` +
   `ClientSession` → `initialize()` → `call_tool()`.
3. **Замеры (stdio, тёплый сеанс)**:
   | Метрика | Значение |
   |---|---|
   | Подъём транспорта (spawn пайпов) | ~13 мс |
   | `initialize()` (однократно на сеанс) | 1.25 с |
   | Холодный вызов инструмента | 3.0–3.5 мс |
   | Тёплые вызовы (10 шт) | 1.0–2.8 мс, медиана ~1.6 мс |
   | Всего сеанс (старт+инит+13 вызовов) | 0.14–0.45 с |
   Латентность пренебрежима против стоимости операций ядра (UIA-зонд ~20–50 мс,
   сценарии секунды).
4. **Кириллица на весь круг** (клиент → сервер → клиент) — byte-perfect
   (`«Шаг за шагом: Мираж на кириллице…»`, 45 знаков, `roundtrip_ok: true`).
   Грабля Windows с OEM-кодировкой консоли на этом пути не проявилась
   (both стороны пишут байты UTF-8 в пайпы, консоль не участвует).
5. **Контракт результата**:
   - обычный dict → текстовый JSON-блок (`content[0].text`), `structured_content` пуст;
   - аннотированный возврат (pydantic-модель) + `@server.tool(structured_output=True)`
     → `output_schema` публикуется, `structured_content` наполняется и валидируется
     клиентом. **Решение для этапа 2**: строгие результаты (вердикты стражей,
     постусловия сценария) отдавать типизированными моделями с
     `structured_output=True`; мягкие справочные — dict-ом.
   - ловушка SDK 2.x: поля моделей snake_case (`server_info`, `structured_content`,
     `is_error`) — camelCase-обращения дают тихий `None`.

## Решение по шагу 0

Официальный SDK подходит: транспорт и кодировки держат, латентность ничтожна,
безопасность не ограничивается. `fastmcp`-запаска не требуется.

## Важное открытие для дизайна инструментов

`structured_output=True` выводит схему из аннотации возврата — это даёт шанс
зафиксировать на уровне схемы **двоичный вердикт** (`ok`, `refused`, `evidence`)
так, что клиент хост-LLM видит контракт инструмента, а не догадывается по тексту.
Отказ стража (`expect_hwnd` не совпал) должен возвращаться как нормальный
типизированный результат `guard_refused: true`, а не как исключение/протокол-ошибка
(склонность SDK: исключение любого резолвера превращается в `UnexpectedToolError`,
и стек уходит в лог сервера).
