## Как возобновить работу

```powershell
cd D:\BOT\MCP-Hands
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.lock.txt   # 89 пакетов, нужен интернет
.venv\Scripts\python.exe -m pytest -q                                # ожидаем 248 passed
```

**Проверено 19.10.2026:** восстановление из слепка выполнено, сьют прогнан — **248 passed**
(2 минуты 8 секунд), живой smoke слоя: `health`, `windows_list` (7 окон), `observe` — всё
отвечает, канон 38 инструментов синхронен с диспетчером.

**Нюанс слепка:** `requirements.lock.txt` содержит `torch==2.14.1+cu126` и
`torchvision==0.29.1+cu126` — это опциональный VLM-путь спайка (этап 0). Такие колёса живут
только на индексе PyTorch, и `pip` из PyPI не разрешает их вовсе — поэтому в слепке строки
закомментированы с подсказкой:

```powershell
.venv\Scripts\python.exe -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cu126
```

Без них сьют проходит полностью (VLM-тесты опциональны).

Живой слой: запустить `tools\opera_debug_launcher.py` для работы в сессии владельца.
Ассистент: `jarvis_panel.bat` (модели Piper при необходимости скачать заново).

## Перезапись истории 19.10.2026 (по блокеру аудита публикации v32)

Аудит публикации нашёл в истории личные строки: сообщение коммита с тестовой задачей
(Telegram) содержало название личного чата владельца и текст сообщения, и тот же текст лежал
в литерале теста `live_type_layer.py`. Мой прежний скан (`git log -S`) искал только по
содержимому диффов и **не смотрел сообщения коммитов** — аудитор был прав, проверка была
неполной.

Что сделано: бэкап-бандл всей истории снят вне проекта
(`%TEMP%\mcp-hands-before-scrub.bundle`, 1.3 МБ), затем один проход `git filter-repo`
с `--replace-text` и `--replace-message` заменил личные строки и в содержимом, и в сообщениях
(67 коммитов переписано). Прежние объекты удалены из репозитория (`reflog expire` + `gc --prune`),
ветка и тег `v0.9-frozen` перезаписаны на сервере (`--force-with-lease`).

Практические следствия, которые надо знать:

- **верхние коммиты сменили SHA**: `77d9f6b → d13c1a1`, `d778baf → 57c6675`,
  `c8b140d → 669a387`; остальные коммиты из документов (0f5a459, 8c4ac4a, d24fe06 и т. д.)
  не переписывались и остались валидными;
- архивы `ForAgentsSpeak/to_review/STAGE_INFO_v*.md` (вне git) сохраняют до-rewrite SHAs —
  это исторический архив процесса, а не действующая документация;
- на стороне GitHub старые объекты могут оставаться доступными по прямому SHA до сборки
  мусора платформой; репозиторий приватный и форков/звёзд не имеет, поэтому риск оценивается
  как исчезающе малый (решение владельца — открывать репозиторий после этой перезаписи).
