# Сравнение путей на одной задаче: встроенный браузер против MCP-Hands

**Дата:** 19.10.2026. **Задача (одна и та же):** открыть новую вкладку YouTube → найти
последнюю новостную сводку Майкла Наки «ДЕНЬ \*\*\*» → открыть видео → включить →
развернуть на весь экран → поставить на паузу.

**Замеры:** встроенный браузер (ZCode In-app Browser, скилл `control-browser`) и MCP-Hands
(детерминированный рецепт + постусловия). Оба дошли до результата; ниже — время каждого
шага, стоимость в обращениях к модели и что каждый путь умеет такого, чего не умеет другой.

## Встроенный браузер (модель в контуре на каждом шаге)

| Шаг | Внутри вызова | Замечание |
|---|---|---|
| создание вкладки | 0.13 с | своя вкладка встроенного браузера, 1280×720 |
| переход + загрузка поиска | 2.94 с | прямой URL поиска |
| чтение выдачи (12 названий) | 1.06 с | через локатор Playwright |
| клик по сводке «ДЕНЬ 1698» | 0.21 с | найден по тексту |
| включение | 0.06 с | `video.play()` |
| полный экран (клавиша «f») | 1.01 с | доверенная клавиша страницы |
| пауза (клавиша «k») | 0.53 с | — |
| **механика итого** | **≈6.0 с** | — |

**Стоимость пути:** 8 обращений к модели (два — только на перечисление и повторное
перечисление вкладок), плюс ~10 КБ служебного описания API в контексте, плюс три неудачных
вызова из-за ошибок интеграции: выдуманный id вкладки, локатор `body` оказался скрыт,
`keys` ожидал массив, а не строку. Каждый такой промах — отдельный круг рассуждения модели.
Итог по ощущениям и фактам: **быстрая механика, дорогое сопровождение**.

## MCP-Hands (детерминированный рецепт, модель не участвует)

| Шаг | Время | Замечание |
|---|---|---|
| старт своего профиля Opera | 6.12 с | холодный старт браузера (разовая цена) |
| своя новая вкладка | 0.28 с | — |
| открытие поиска | 2.27 с | прямой URL поиска |
| выбор по признаку «ДЕНЬ»+канал и запуск | 3.27 с | чтение выдачи и выбор ролика |
| полный экран | 3.32 с | JS-вызов, затем доверенная клавиша «f» с проверкой |
| пауза | 0.02 с | — |
| **итого по шагам** | **15.28 с** | из них 6.12 с — холодный старт |

**Стоимость пути:** ноль токенов (цепочка детерминированная), одно обращение к модели за
всю задачу. Факт подтверждён постусловиями: канал «Майкл Наки», ролик «ДЕНЬ 1698…», полный
экран=True, пауза=True. Живая Opera владельца была уже закрыта (порт 9222 не отвечает),
поэтому замер сделан на своём профиле — в его сессии путь тот же, только без холодного старта
(и со входами владельца).

## Что нашли в этом сравнении (и починили сразу)

- **Отказ `connect_user` не был виден в сводке**: инструмент возвращал `ok=false` с причиной,
  но сводка гласила просто «живой браузер: connect_user» — агент, читающий только сводку,
  принял бы это за успех и пошёл работать с пустой сессией (мой же скрипт так и сделал).
  Исправлено: сводка теперь несёт «— НЕ ВЫШЛО: <причина>».
- Живая Opera владельца закрылась по ходу теста: наш путь честно деградирует на свой профиль,
  встроенный браузер этого не замечает, потому что работает в своём экземпляре.

## Честный вердикт

**Механика внутри шага** быстрее у встроенного браузера (≈6 с против 15 с), главным образом
из-за холодного старта нашего браузера и более осторожных проверок.

**Стоимость задачи** несопоставима в пользу MCP-Hands: ноль токенов и одно обращение против
восьми обращений с десятком килобайт служебного контекста и трёх неудачных вызовов.
Разница растёт с повторами: рецепт повторяется за секунды и бесплатно, модель — нет.

**Покрытие** пока в пользу встроенного: он берётся за новую страницу без рецепта (и это его
сильная сторона), мы — только за то, для чего есть примитивы и рецепт (или за план модели,
но это уже платный путь с десятками секунд).

**Сессия и приватность** в пользу MCP-Hands: он работает в ЖИВОЙ Опере владельца (Telegram,
учебные сайты со входами), а встроенный — в своём отдельном окне без его сессий.

**Вывод, который я готов защищать:** это не «или-или», а два разных инструмента.
Встроенный браузер — универсальный разведчик и исполнитель новых задач в изолированном окне.
MCP-Hands — дешёвый, повторяемый, проверяемый исполнитель на живом рабочем столе владельца.
Стратегия для проекта: не соревноваться в универсальности, а наращивать библиотеку
примитивов и рецептов на реальных задачах владельца — там, где важны повторы, его сессия,
приватность и честная проверка фактом.
